# 데이터 관리 화면 테스트용 ERP CSV

구매팀 "데이터 관리" 화면(`/purchasing/data-management`)의 **업로드 → 품질검사 → 검토 → 승인/거부**
흐름을 손으로 확인할 때 쓰는 파일 묶음이다. 아래 기대 결과는 `ErpImportService.preview()`로
실제 돌려서 얻은 값이다(DB에 시드가 없는 상태 기준).

## 파일명을 바꾸지 말 것

대상 테이블은 **파일명으로 먼저 판별한다**(`ErpImportService.detect()`).
`01_materials.csv` → 앞의 `01_`을 떼고 `materials` 테이블로 본다.
이름을 바꾸면 헤더 서명으로 추정하는 경로로 넘어가고, 그것도 실패하면 "대상 테이블 미판별" 오류가 난다.

## pass/ — 통과 (승인 버튼이 바로 열림)

| 항목 | 값 |
|---|---|
| 판정 | 전체 파일 SUCCESS |
| DB 반영 가능 | **true** |
| 행 수 | 16 |
| 오류 / 경고 / 중복 | 0 / 0 / 0 |
| 품질점수 | **100** |

ERP 10종 전체를 FK 의존 순서대로 담은 자급자족 묶음이다. 계약이 참조하는 자재·공급사가
같은 배치 안에 있어서 DB가 비어 있어도 FK가 풀린다. **10개를 한 번에 올려야 한다** —
`04_contracts.csv`만 따로 올리면 자재를 못 찾아 오류가 난다.

경고까지 0으로 맞추려고 `created_at` / `updated_at` / `available_capacity_quantity`처럼
**적재되지 않는 컬럼은 헤더만 두고 값을 비웠다.** 값이 들어 있으면 "이 컬럼은 적재되지 않고
무시됩니다" 경고가 붙는다(실제 시드 파일이 그렇다).

ID에 전부 `TEST` 를 붙여서 기존 시드 데이터와 겹치지 않는다. 승인하면 진짜로 DB에 들어가고,
같은 파일을 다시 승인하면 신규 삽입이 아니라 **갱신**으로 잡힌다(upsert라 반복 테스트해도 안전하다).

## warning/ — 경고만 있음 (승인 가능하지만 확인 모달이 뜸)

| 항목 | 값 |
|---|---|
| 판정 | WARNING |
| DB 반영 가능 | **true** |
| 행 수 | 10 |
| 오류 / 경고 / 중복 | 0 / 3 / 1 |
| 품질점수 | **86** |

`01_materials.csv` 한 개짜리다. 승인 버튼은 열리지만 누르면
*"경고 3건과 중복 1건이 있습니다…"* 확인 모달이 먼저 뜬다 — 이 경로를 보려면 이 세트를 쓴다.

심어둔 것:

- `created_at`, `updated_at` 에 값이 있음 → 경고 2건 (적재되지 않고 버려지는 값)
- `비고` — 시스템에 없는 컬럼 → 경고 1건
- 마지막 줄 `MAT-TEST-W1` 이 첫 줄과 중복 → 중복 1건

## fail/ — 실패 (승인 버튼 잠김)

| 항목 | 값 |
|---|---|
| 판정 | 전체 파일 ERROR |
| DB 반영 가능 | **false** |
| 오류 / 중복 | 14 / 1 |
| 품질점수 | **0** |

오류 유형을 골고루 넣었다. 6개를 한꺼번에 올리면 오류 목록 필터·검색·페이지네이션과
"오류를 수정한 후 다시 업로드해 주세요" 문구를 한 번에 볼 수 있다.

| 파일 | 심어둔 오류 |
|---|---|
| `01_materials.csv` | 필수 컬럼(`material_name`) 자체가 없음 · `active=maybe`(불리언 아님) · `material_code` 값이 빔 · 키 중복 |
| `02_suppliers.csv` | 따옴표가 닫히지 않음 (해당 줄 파싱 실패) |
| `03_warehouses.csv` | 공백 줄만 있음 → "빈 파일입니다" |
| `04_contracts.csv` | FK 2건 미해결 · `2026-13-45`(없는 날짜) · `indexed_at`에 타임존 오프셋 없음 |
| `06_inventory_snapshots.csv` | 숫자 아닌 값 · 컬럼 수 부족(13개 헤더에 6개) · FK 2건 미해결 |
| `unknown_data.csv` | 파일명·헤더 어느 쪽으로도 대상 테이블을 알 수 없음 |

`06_inventory_snapshots.csv`의 FK 오류는 `MAT-TEST-LI` · `WH-TEST-01`을 참조하는데
이 배치에 자재·창고 파일이 없어서 난다. **pass/ 를 먼저 승인해 DB에 넣어두면 그 두 건은 사라지고**
나머지 오류만 남는다 — "같은 파일인데 배치 구성에 따라 FK 판정이 달라진다"를 확인하기 좋다.

## UI에서는 못 올라가는 케이스 (API 직접 호출용)

프론트가 파일 선택 단계에서 먼저 거르는 것들이라, 화면으로는 서버까지 도달하지 않는다.

- **0바이트 파일** — 프론트가 "빈 파일입니다"로 차단. `fail/03_warehouses.csv`는 공백 3바이트라
  프론트를 통과하고 백엔드의 빈 파일 검증까지 도달한다.
- **`.csv`가 아닌 파일** — 프론트가 확장자로 차단. 백엔드에도 같은 검사가 있다.
- **최대 크기 초과** — `GET /api/v1/erp/imports/constraints`가 알려주는 값(기본 50MB) 기준.

백엔드 쪽 검증을 직접 보려면 `curl`로 `POST /api/v1/erp/imports/preview` 를 때리면 된다.

## 보고서까지 같이 보려면

- **pass/** 올려서 검사 → `검증 보고서 PDF` → 승인 → `최종 반영 보고서 PDF`
  (승인 전/후 보고서의 문구와 파일명이 다르다)
- **fail/** 올려서 검사 → `검증 보고서 PDF`로 오류 목록이 실리는지 확인
- 오류가 100건을 넘겨야 `전체 오류 CSV` 버튼이 뜬다. 이 세트는 14건이라 안 뜬다 —
  보려면 `fail/01_materials.csv`의 잘못된 행을 100줄 넘게 복사해 늘리면 된다.
